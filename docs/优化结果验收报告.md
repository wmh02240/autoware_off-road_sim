# 双车型优化结果验收报告

验收日期：2026-10-06  
验收依据：[《当前双车型模型问题分析与优化优先级》第 9 章](./当前双车型模型问题分析与优化优先级.md#9-验收标准)

## 1. 验收范围

本次分别对以下模型进行独立启动和运行时采样：

- `RoboRacer_OffRoad`，ROS 命名空间为 `/opponent`；
- `RoboRacer_Max`，ROS 命名空间为 `/ego`。

验收采用 `scripts/configs/lariad_hard.yaml`，每次只启用一辆车。测试完成后配置已恢复为默认状态：OffRoad 启用、Max 关闭。

运行时证据由 `scripts/tools/validate_ros_acceptance.py` 采集，包括图像消息布局、时间戳交集、CameraInfo 内参、IMU、PointCloud2、静态 TF 和动态 TF。车轮动态项另外通过 `/drive` 发送直行指令后复测。

## 3. 本轮验收中发现并修复的问题

### 3.1 Max 主相机缺少 CameraInfo

> 说明：本节记录的是话题规范化之前的原始验收结果。当前双目图像已改为
> `/ego/left/image_raw`、`/ego/right/image_raw` 及对应的 `camera_info`；Max
> 独立彩色主相机仍保留 `/ego/rgb`。

首轮运行时只有左右目和伪深度 CameraInfo，主 `/ego/rgb` 与 `/ego/depth` 没有 `/ego/camera_info`。现已复用主相机已有 Render Product 补建 CameraInfo Helper，不重复发布图像。复测得到：

- `/ego/rgb`：`rgb8`、`1280×720`、`ego/camera_color_optical_frame`；
- `/ego/depth`：`32FC1`、`1280×720`、`ego/camera_color_optical_frame`；
- `/ego/camera_info`：内参有效，`fx=fy≈634.086`，主点为 `(640, 360)`；
- 三个话题存在完全相同的采样时间戳。

### 3.2 Max 底盘运动参考误用了组织层 Xform

Max 的 `/Rigid_Bodies/Chassis` 是里程计所需的 PhysX 刚体，但用于语义外参和车轮相对位姿的运动基准应为其子 Prim `Chassis/base_link`。此前统一使用 Chassis 容器，会在车辆运动时让车轮位置相对错误参考系转动。

现已拆分为：

- 里程计刚体：`/Rigid_Bodies/Chassis`；
- ROS `base_link` 位姿参考：`/Rigid_Bodies/Chassis/base_link`。

修复后，Max 四轮在 `base_link` 下形成规则矩形，车辆运动时轮轴中心保持稳定。

### 3.3 车轮原点和轴向采用不同的可信来源

车轮 TF 现在采用：

- 视觉根 Mesh 的平移：确定真实轮轴中心；
- Wheel 刚体的旋转：反映实际转向和滚动姿态。

这样避免了刚体 CAD 原点聚集在车体中心，也避免将 Mesh 自带的显示旋转误认为物理轴向。

### 3.4 缺失与关闭状态的日志语义不清

启动日志现在分别报告：

- 模型不存在的传感器：`model does not provide ...; no publisher will be created`；
- 模型具备但配置关闭的传感器：`available but disabled by configuration`。

因此 `off` 状态不再混淆“模型没有”和“用户关闭”。

## 4. 关键实测数据

### 4.1 OffRoad

- 四轮中心（`base_link` 下，单位 m）：
  - 前左：约 `(0.204, 0.168, 0.002)`；
  - 前右：约 `(0.261, -0.044, -0.001)`；
  - 后左：约 `(-0.028, 0.106, 0.001)`；
  - 后右：约 `(0.029, -0.104, -0.001)`。
- 深度有效布局：`1280 × 720 × 4 = 3686400 bytes`。
- 均匀抽样 4096 个深度值时，约 68% 为有限正深度；其余主要为天空/无命中区域的无穷远值，未发现字节错位或乱码特征。
- 启动日志明确指出模型不具备 `realsense_imu`、`lidar`、`radar`。

### 4.2 Max

- 四轮中心（`base_link` 下，单位 m）：
  - 前左：约 `(0.481, 0.218, 0.019)`；
  - 前右：约 `(0.481, -0.218, 0.017)`；
  - 后左：约 `(0.001, 0.218, 0.018)`；
  - 后右：约 `(0.001, -0.215, 0.020)`。
- LiDAR 点云：`262144` 点、`point_step=16`、字段为 `x/y/z/intensity`、总数据长度 `4194304 bytes`，布局有效。
- LiDAR 外参：`base_link -> lidar_link ≈ (0.368, 0, 0.252) m`。
- 主 IMU、RealSense IMU、LiDAR 和四个相机 optical frame 均已接入同一 TF 树。
- 启动日志明确指出模型不具备 `radar`。

## 5. 非阻断观察项

- Max 同时启用多相机和 RTX LiDAR 后，当前机器实时因子约为 `15%～22%`；首次运行还会触发较长的 RTX 着色器编译。该问题影响启动和实时性能，但不影响本次 9 项数据正确性验收。
- 切换模型的一次启动中，Isaac Sim 6.0.1 的 `librtx.hydra.so` 发生原生崩溃并退出 139；清理残留进程后重启成功，复测未复现。建议后续将“连续启动/退出 10 次”作为稳定性专项测试，而不与本章功能验收混合。
- 静止车辆在不平地面上仍会出现毫米到厘米级的物理沉降或缓慢滑移；本次判据检查的是 TF 连续性和参考体正确性，而不是把物理车辆强制锁定为零速度。

## 6. 复现命令

```bash
# 仿真启动后，验收 OffRoad
source /opt/ros/humble/setup.bash
python3 scripts/tools/validate_ros_acceptance.py \
  --namespace opponent --duration 5

# 将配置切换为只启用 Max 后验收
python3 scripts/tools/validate_ros_acceptance.py \
  --namespace ego --duration 7 \
  --expect-lidar --expect-realsense-imu
```

最终结论：第 9 章的 9 项功能验收标准均已满足；RTX 首次编译耗时和一次 Hydra 原生崩溃记录为后续稳定性与性能专项观察项。
